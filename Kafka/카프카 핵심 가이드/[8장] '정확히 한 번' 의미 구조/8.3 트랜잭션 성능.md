# 8.3 트랜잭션 성능 (p225)

- 프로듀서 측 오버헤드
  - 트랜잭션 사용 시 약간의 오버헤드 발생
  - **트랜잭션 ID 등록**: 프로듀서 생성 시 단 한 번
  - **파티션 등록**: 트랜잭션 내 각 파티션당 최대 한 번
  - **커밋 요청**: 각 파티션마다 커밋 마커 추가
    - **동기적 처리**: 성공/실패/타임아웃 완료 전까지 데이터 전송 불가 → 오버헤드 증가

  - **메시지 수와 무관**
    - 트랜잭션 내 메시지가 많을수록 상대적 오버헤드 감소
    - 동기적 단계 수행 횟수 감소 → 처리량 증가

<br>

- 컨슈머 측 오버헤드
  - 커밋 마커를 읽는 작업 관련 약간의 오버헤드 존재
  - **read_committed 모드**:
    - 아직 완료되지 않은 트랜잭션 메시지 **리턴되지 않음**
    - 트랜잭션 커밋 사이 간격이 길면 메시지 리턴 대기 시간 증가 → 종단 지연 증가

  - **장점**:
    - 컨슈머는 아직 완료되지 않은 트랜잭션 메시지를 **버퍼링할 필요 없음**
    - 브로커가 읽기 요청 시 메시지 리턴하지 않음 → 컨슈머 추가 작업 없음
    - 결과적으로 **처리량 감소 없음**
