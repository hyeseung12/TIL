# 4.5 컨슈머 설정하기 (p94)

## Fetch 관련 옵션 (메시지 가져오기)

- `fetch.min.bytes` : 컨슈머가 브로커로부터 레코드를 얻어올 때 받는 데이터의 최소량 지정
  - default : 1byte
   - (레코드 양) < (fetch.min.bytes) 일 때, 새로운 데이터가 더 쌓일 때까지 기다리고 보내준다.
   - 해당 옵션 값이 작으면, 자주 fetch 되기 때문에 네트워크 오버헤드가 발생하며,
   - 해당 옵션 값이 클수록, 쌓일 떄까지 기다리기 때문에, 지연이 발생한다.

- `fetch.max.wait.ms` : 카프카가 컨슈머에게 응답하기 전 충분한 데이터가 모일 때까지 얼마나 오래 기다릴 것인가를 결정한다.
   - default : 500ms (type: int)
   - 이 이상의 시간까지 기다린 경우, 데이터가 적더라도 fetch를 한다.
   - -> 따라서, `fetch.min.bytes` || `fetch.max.wait.ms` 둘 중 하나의 조건이 맞는 경우 레코드를 리턴합니다.

- `fetch.max.bytes` : 컨슈머가 브로커를 폴링할 때 카프카가 리턴하는 최대 바이트 수를 지정합니다.
   - default : 50MB (단, 카프카 버전 3.1은 57671680 (55 mebibytes))
   - 컨슈머가 서버로부터 받은 데이터를 저장하기 위해 사용하는 메모리의 양을 제한하기 위해 사용합니다. (얼마나 많은 메시지를 받았는지와는 무관)
   - 브로커는 해당 바이트 값을 넘겨도, 그대로 전송합니다.
     - 이는, 컨슈머가 계속 읽게 하는 것을 보장합니다.

- `max.poll.records` : poll()을 호출할 때마다 리턴되는 최대 레코드 수
  - default : 500
   - 크기가 아닌, 개수입니다.

- `max.partition.fetch.bytes` : 서버가 파티션별로 리턴하는 최대 바이트 수를 결정합니다.
  - default : 1MB
   - poll()이 ConsumerRecords를 리턴할 때, 메모리 상에 저장된 레코드 객체의 크기는 컨슈머에 할당된 파티션 별로 해당 옵션 크기 까지 차지할 수 있습니다.
   - 브로커가 얼마나 많은 파티션이 포함되었는지 결정할 수 있는 방법이 없어 -> 해당 옵션 값을 사용해서 메모리 사용량을 조절하는 것은 꽤 복잡합니다.
   - 따라서, 특별한 이유가 없으면 `fetch.max.bytes` 사용을 강력히 권장한다.

## Session / Heartbeat 관련 옵션 (Consumer Group 유지)

- `session.timeout.ms` : 컨슈머 하트비트가 올 때까지 기다리는 타임아웃 시간
  - default : 카프카 버전 3.0 이후부터 45초 (그 이전은 10초)
  - 이 후 시간은 해당 컨슈머가 죽었다고 간주

- `heartbeat.interval.ms` : 얼마나 자주 하트비트를 보낼건지
  - default : 3초
  - -> 보통 heartbeat.interval.ms는 session.timeout.ms의 1/3으로 설정한다. 라는 규칙이 있지만, 기본값은 유효하지 않음.
    - 단, 성급하게 바꾸지 않자. 이 값은 여전히 리밸런스가 진행중인 컨슈머를 탐지해 내는 데 쓰인다.

- `max.poll.interval.ms` : 컨슈머가 폴링을 하지 않고도 죽은 것으로 판정되지 않을 수 있는 최대 시간을 지정
      - default : 5분
  - heartbeat는 백그라운드 스레드로 동작하는데, 이 때 heartbeat가 정상이지만, 스레드가 멈춘 케이스인 경우
    - 컨슈머가 여전히 레코드를 처리하고 있는지 확인하는 간단한 방법은, 컨슈머가 추가로 메시지를 요청하는 지를 확인하는 것이다.
      - 하지만, 요청 사이의 간격이나 추가 레코드 요청은 예측하기 힘들 뿐 아니라 현재 사용 가능한 데이터의 양, 컨슈머가 처리하고 있는 작업의 유형, 때로는 함께 사용되는 서비스의 지연에도 영향을 받는다.

  - 위의 상황으로 인한 해결책으로 처리 시간 조절하는 등의 옵션이 존재한다.
    - `max.poll.records` : 리턴되는 데이터의 양을 조절
    - `max.poll.interval.ms` : 컨슈머가 폴링을 하지 않고도 죽은 것으로 판정되지 않을 수 있는 최대 시간을 지정
      - 타임아웃이 발생한 경우, 'leave group' 요청을 보내 하트비트 전송을 중단합니다.

## Timeout / Request 관련 옵션

- `default.api.timeout.ms` : API를 호출할 때 명시적인 타임아웃을 지정하지 않는 한, 거의 모든 컨슈머 API 호출에 적용되는 타임아웃 값
  - default : 1분
    - 해당 기본 값은, 요청 타임아웃 기본값보다 커 피룡할 경우 이 시간 안에 재시도 할 수 있다.
  - 해당 옵션이 적용되지 않은 대표적인 예시로 poll()이 있다.
    - 해당 메서드는 호출할 때 명시적으로 poll(duration) <- 으로 명시적인 타임아웃을 지정한다.

- `request.timeout.ms` : 컨슈머가 브로커로부터의 응답을 기다릴 수 있는 최대 시간
  - default : 30초
    - 더 내리지 않는 걸 권장. 브로커에 요청을 처리할 시간을 충분히 주는게 중요
  - 해당 시간 동안 브로커가 응답을 받지 않으면, 연결을 닫은 뒤 재연결을 시도한다.

<br>

## Offset / Commit 관련 옵션

- `auto.offset.reset` : 컨슈머가 예전에 오프셋을 커밋한 적이 없거나, 커밋된 오프셋이 유효하지 않을 때, 파티션을 읽기 시작할 때의 작동을 정의한다.
  - default : 'latest' : 가장 최신 레코드를 읽는다. (즉, 컨슈머가 작동하기 시작한 다음부터 쓰여진 레코드)
  - 'earliest' : 맨 처음부터 모든 데이터를 읽는 방식
  - 'none' : 유효하지 않은 오프셋부터 읽으려 할 경우 예외 발생

- `enable.auto.commit` : 컨슈머가 자동으로 오프셋을 커밋할지의 여부를 결정한다
  - default : true
  - true 인 경우, `auto.commit.interval.ms` 와 같이 사용해서 얼마나 자주 커밋할 지 결정 가능
  - false 인 경우, 언제 커밋할지 직접 결정 가능

- `offsets.retention.minutes` (p101) : 컨슈머 그룹이 빌 때, 카프카는 커밋된 오프셋을 이 설정값에 지정된 기간 동안만 보관한다.
  - default : 7일

<br>

## Group / Client 관련 옵션

- `partition.assignment.strategy` : 파티션 할당 전략
  - default : 카프카 3.1 버전 기준으로 -> [RangeAssignor, CooperativeStickyAssignor] (아직 최신 버전 4.1에서도 동일하게 적용되어 있음)
    - RangeAssignor의 첫 번째 배열값이 사용되며 -> 이는 default가 현재 RangeAssignor 이라는 것을 명시함.
    - -> CooperativeStickyAssignor을 사용하고 싶다면 리스트에서 RangeAssignor을 삭제하라고 공식 문서에 명시되어 있음.
    - https://kafka.apache.org/31/documentation.html#consumerconfigs_partition.assignment.strategy

- `client.id` : kafka client 식별자

- `client.rack` : 가장 가까운 레플리카로부터 메시지를 읽어올 수 있게 해줌.
  - replica.selector.class 기본값을 `org.apache.kafka.common.replica.RackAwareReplicaSelector`로 잡아주면 된다.

- `group.instance.id` : 정적 그룹 멤머십 설정

<br>

## 네트워크 / 버퍼 관련 옵션

- `receive.buffer.bytes, send.buffer.bytes` : TCP 수신 및 수신 버퍼의 크기
  - default : 카프카 3.1 버전 기준으로 -> 32768 (32 kibibytes), 131072 (128 kibibytes)
  - -1은 운영체제 기본값으로 한다.
