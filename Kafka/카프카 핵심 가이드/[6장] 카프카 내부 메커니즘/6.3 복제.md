# 6.3 복제 (p158)

<img src="https://velog.velcdn.com/images/doolchong/post/f08dca50-42ee-48d4-b8a3-c0e18a1fc18e/image.png">

- 리더는 모든 쓰기 요청을 받고, 레코드를 읽을 수 있다.
  - 어느 팔로워 레플리카가 리더 레플리카의 최신 상태를 유지하고 있는지 확인해야 한다.
    - 팔로워 레플리카의 조회 요청에 응답으로, 오프셋을 포함하고 + 언제나 메시지를 순서대로 돌려 준다. -> 새로 추가된 메시지 여부를 알 수 있고, 얼마나 팔로워가 뒤쳐져 있는지도 확인 할 수 있다.
- 팔로워는 리더를 제외한 파티션의 모든 레플리카라고 한다. 별도로 설정을 잡아주지 않는 한, 팔로워는 클라이언트의 요청을 처리할 수 없다.
  - 이들의 역할은 최근 메시지들을 복제함으로 -> 최신 상태를 유지하는 것이다.
  - 읽기 기능으로 가장 가까이에 있는 인-싱크 레플리카로부터 읽을 수 있는 기능이 추가가 되었다. -> 네트워크 트래픽 비용 감소

- 일정 시간동안 팔로워 레플리카가 읽기 요청을 보내지 않거나, 추가된 메시지를 따라잡지 못하면 -> 해당 레플리카는 동기화가 풀린 것으로 간주한다. ('out-of-sync replica')
  - in-sync replica는 이와 반대로, 최신화된 레플리카이다.
  - 일정 시간 동안이라는 옵션은 -> `replica.lag.time.max.ms` 으로 결정된다.
    - default : 카프카 3.1 버전 기준으로 30초

- 선호 리더란 토픽 파티션이 처음 생성되던 시점에 리더 레플리카이다.
  - `auto.leader.rebalance.enable` = true이고 현재 리더와 동기화되고 있담녀, 선호 리더를 현재 리더로 만든다.
